# PolicyForge — site/

This directory contains the PolicyForge marketing site. It is intentionally simple: four files, no build step, no JavaScript framework. Everything is static HTML/CSS/SVG.

## Files

| File | What it is |
|---|---|
| `index.html` | The landing page. Single self-contained HTML file (~46KB) with all CSS inlined. |
| `demo.svg` | Animated CLI demo (~18KB). Self-contained SVG with SMIL animations. Embedded into the landing page hero. Plays for ~21 seconds, loops forever. |
| `blog-why-this-exists.html` | The "Why PolicyForge exists" essay, styled to match the landing page. |
| `blog-why-this-exists.md` | Markdown source of the same essay, for reposting to dev.to / Medium / Hacker News if useful. |

## Design tokens

If you're modifying the styles, both pages use the same CSS variables in their `:root` block. The palette is:

- `--teal-deep: #0f3a3a` — primary, used for headlines and the dark section
- `--terracotta: #c8553d` — accent, reserved for the most important callouts
- `--cream: #faf6ee` — page background (warm off-white, not paper white)
- `--charcoal: #1a1a1a` — body text and the terminal background

Typography: Fraunces (display serif) + IBM Plex Sans (body) + IBM Plex Mono (code), all loaded from Google Fonts.

## Deploying to GitHub Pages

The simplest path:

1. Push the contents of this directory to the repo's `docs/` folder, OR push them at the root of a `gh-pages` branch.
2. In repo Settings → Pages, set the source.
3. The site will be live at `https://sadranyi.github.io/PolicyForge/`.

If you'd rather use a custom domain (`policyforge.dev`, for example):

1. Buy the domain.
2. Add a CNAME record pointing to `sadranyi.github.io`.
3. Add a `CNAME` file to this directory containing just the domain name (no protocol, no path).
4. In Settings → Pages, set the custom domain and enable HTTPS.

## Updating the demo

The `demo.svg` was generated by a Python script (`/scripts/build-demo-svg.py` in the broader project; not in `site/` to keep the published surface clean). To regenerate:

```bash
python3 scripts/build-demo-svg.py
```

The script defines the demo's content as a list of lines with timing offsets. Edit that list to change what the demo shows.

## Updating the landing page

It's a single HTML file. Edit `index.html` directly. The animations in the hero are defined in CSS at the top of the file (`@keyframes fadeUp`); section styling is grouped by `/* === Section === */` comments to make it easier to find what you're editing.

## What's intentionally not here

- **No JavaScript framework.** Plain HTML/CSS. Easier to maintain, faster to load, no build step.
- **No analytics.** The site doesn't track visitors. The README claims "0 tracking" and we mean it.
- **No CDN dependencies** other than Google Fonts (which is already cached for most visitors).
- **No images.** Every visual on the page is a CSS-rendered element or the SVG demo. Means no image hosting, no broken links, no CDN bills if traffic spikes.
